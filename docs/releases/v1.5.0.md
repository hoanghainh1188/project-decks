Sheafly 1.5.0 connects to the task tracker your team already uses. Pull issues from **Backlog** or **Jira Cloud** into a project, plan and level them in Sheafly, and push the dates you computed back, with a preview before anything is written and a conflict to settle whenever both sides changed the same field. It also lets you paste rows copied from a spreadsheet, select ranges of tasks with the keyboard, and makes edits on large projects faster.

> **Please read before using the tracker sync.** It was written from the Backlog and Jira API documentation and tested against sample responses, but it has **not yet been run against a real Backlog space or Jira site**. A push writes to your tracker, so try it on a test space or project first.

## What's new

### Task tracker sync (Backlog and Jira Cloud)
- **Pull.** File → Import → Pull from Task Tracker brings the issues of one project into the open project. Pick the tracker, the site, the project key and an optional filter (search parameters for Backlog, a JQL condition for Jira), fetch with progress and a Stop button, see what would be added, changed or marked as gone from the source, and apply it as one undo step. Pulling again with nothing new at the source changes nothing.
- **What comes across.** Title, effort, due date, status (as progress), parent issues (as groups), custom fields of the same name, and the assignee, matched by the email on each resource (Resources view → Email) or, when Jira hides emails, by name. Jira also brings "blocks" links as finish-to-start links, and takes story points from a number field you name, turned into hours.
- **Push.** File → Export → Push Dates to Task Tracker writes the start and finish days Sheafly computed, and optionally the assignee, to the issues. You choose what to write, see exactly what will change at the source, and only then press the button that writes. By default only empty fields are filled; nothing is ever cleared. The days can go to a date field of their own, so the tracker's due date (which a pull reads as the deadline) is left alone.
- **Conflicts.** Sheafly remembers what each side held at the last sync. A pull no longer overwrites an edit you made when the source did not change that field. When the same field changed on both sides, to different values, it is listed as a conflict and nothing applies until you choose, field by field or for all, to take the source's value or keep Sheafly's.
- **Configurable.** Project → Project Setup → Task Tracker Sync sets, per field, which way it syncs (both ways, pull only, push only, off), what happens on a conflict (ask, source wins, Sheafly wins), which field at the source to read or write, and the constants (percent of an in-progress issue, the hour of a date, hours per story point). "Check against the source" confirms the named fields exist before you save.
- **Your keys stay on your computer.** The API key (and for Jira the account email) is kept in the operating system's credential store, never in the project file, and Sheafly sends it only to Backlog (`*.backlog.com`, `*.backlog.jp`, `*.backlogtool.com`) and Jira Cloud (`*.atlassian.net`) sites.

### Editing
- **Paste from a spreadsheet.** Rows copied from Excel, Numbers or Google Sheets open the import dialog, like a file.
- **Select ranges with the keyboard.** Shift+arrow keys extend the task selection on the Gantt, and Shift+click selects a range of boxes on the network diagram.
- **Custom fields.** Choose which custom field columns show in the task sheet; the Gantt PDF and copied text include them.

### Speed
- After an edit, undo or redo, Sheafly sends only what changed in the project to the interface instead of the whole project, so edits on projects with thousands of tasks stay quick.

### Other
- Effort ranges for the finish forecast now travel through MSPDI.

## Install

| System | File |
|---|---|
| macOS (Apple Silicon and Intel) | `Sheafly_1.5.0_universal.dmg` |
| Windows | `.msi` or `-setup.exe` |
| Linux | `.AppImage`, `.deb` or `.rpm` |

The installers are **not signed with a developer certificate** yet:
- **macOS:** try to open Sheafly once, then go to **System Settings → Privacy & Security** and click **Open Anyway**.
- **Windows:** if SmartScreen asks, choose **More info → Run anyway**.

## Files

Sheafly 1.5.0 opens every project from 1.0.0 to 1.4.0. **A project saved with 1.5.0 cannot be opened in 1.4.0 or earlier**, because the file format has new kinds of edits (tracker sync, resource emails). Keep a copy if you still share files with someone on an older version. A project you pulled with an earlier build opens fine; its tasks have no sync history yet, so where Sheafly and the source differ the first pull lists a conflict with the last sync marked "unknown" instead of choosing a side.

## Known limitations

- The tracker sync is untested against real services (see above), reads Backlog custom fields tolerantly because the public docs do not show their shape, and for Jira needs a date field you name for start days (Jira has no standard start date).
- Only dates and the assignee are written back; names, effort and status are not. A parent changed at the source is not followed for tasks already in the project. Asana is not supported yet.
- Tracker links, the source and sync settings are kept only in `.sheafly` files, not in MSPDI (resource emails are).
- The interface is in English and Vietnamese only.
- `.mpp` files cannot be read; use MSPDI (`.xml`) to exchange projects with Microsoft Project.
- The installers are not signed with a developer certificate or notarized.
